# Веб-приложение "Атомные привычки"

## Описание:      
    Данное веб-приложение помогает добавить в жизнь пользователя полезные привычки и закрепить их.
    Содержит два отдельных приложения приложения: 
    "habits" - приложение, в котором прописана основная логика приложения;    
    "users" - приложение для регистрации и авторизации пользователей, а также для настройки доступа для 
    авторизированных пользователей. Также в данном приложении содержится информация о платежах пользователей.

    Адрес сервера с развернутым приложением:  158.160.192.46

## Установка и настройка

### Предварительные требования

*   [Git](https://git-scm.com/downloads)
*   [Docker](https://docs.docker.com/get-docker/)
*   [Docker Compose](https://docs.docker.com/compose/install/)

### Клонирование репозитория

```bash
git clone git@github.com:MikhailGubin/atomic_habits.git
cd <название_папки_проекта>
```
### Настройка переменных окружения

Скопируйте файл .env.example и заполните его:

```
cp .env.example
```

Откройте .env в текстовом редакторе и настройте переменные.


Совет: Для генерации SECRET_KEY вы можете использовать команду Python:

```
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

### Запуск проекта
С помощью Docker Compose
Для запуска всех сервисов (PostgreSQL, Redis, Celery, Beat, Django Web):

```
docker-compose up -d --build
```

## CI/CD и Деплой на сервер

### CI/CD с GitHub Actions

    Настроен автоматический пайплайн CI/CD с использованием GitHub Actions. 
    При каждом push в ветку develop происходит следующее:
    
    Сборка Docker-образов: Создаются образы для веб-приложения.
    Тестирование: Запускаются все тесты.
    Деплой: В случае успешного прохождения тестов, пайплайн автоматически разворачивает обновленную версию приложения 
    на сервер в Yandex Cloud.
    
    Настройка: Конфигурация пайплайна находится в файле .github/workflows/ci.yml.
    Для работы деплоя необходимо настроить следующие секреты в репозитории GitHub:
    
    SSH_USER: Пользователь для SSH-подключения к серверу.
    SERVER_IP: IP-адрес вашего сервера в Yandex Cloud.
    SECRET_KEY: Секретный ключ Django для продакшен-среды.
    POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD: Переменные для подключения к PostgreSQL на сервере.
    HOST: Доменное имя или IP-адрес вашего приложения.
    SSH_KEY: Приватный SSH-ключ для подключения к серверу.
    
### Деплой на Yandex Cloud

    Проект развернут на виртуальной машине в Yandex Cloud.
    
    Подготовка сервера:
    
    Создана виртуальная машина с установленной ОС Ubuntu 22.04 LTS.
    Установлены Docker и Docker Compose.
    Настроен SSH-доступ с использованием ключей.
    Процесс деплоя (автоматический через GitHub Actions):
    
    GitHub Actions подключается к серверу по SSH.
    Синхронизирует код проекта (обычно через git pull или копирование файлов).
    Передает продакшен-переменные окружения (через секреты GitHub).
    Пересобирает Docker-образы и перезапускает контейнеры с помощью docker-compose up -d --build.

    Конфигурация Nginx: 
    На сервере настроен Nginx для проксирования запросов к Django-приложению, работающему
    в Docker-контейнере, и для обслуживания статических файлов. Конфигурация Nginx находится в файле nginx.conf,
    который также монтируется в контейнер Nginx через Docker Compose.

## Описание приложений:

1. #### Приложение mailing_service 
##### Описание:        
    Создана модель привычки со следующими полями:
    
    * Пользователь — создатель привычки.
    * Место — место, в котором необходимо выполнять привычку.
    * Время — время, когда необходимо выполнять привычку.
    * Действие — действие, которое представляет собой привычка.
    * Признак приятной привычки — привычка, которую можно привязать к выполнению полезной привычки.
    * Связанная привычка — привычка, которая связана с другой привычкой, важно указывать для полезных привычек, но не для приятных.
    * Периодичность (по умолчанию ежедневная) — периодичность выполнения привычки для напоминания в днях.
    * Вознаграждение — чем пользователь должен себя вознаградить после выполнения.
    * Время на выполнение — время, которое предположительно потратит пользователь на выполнение привычки.
    * Признак публичности — привычки можно публиковать в общий доступ, чтобы другие пользователи могли брать в пример чужие привычки.

    Созданы CRUD для модели привычки. Для реализации CRUD использованы Generic-классы.
    Добавлены следующие валидаторы для привычки:
    * Исключается одновременный выбор связанной привычки и указания вознаграждения.
    * В модели не должно быть заполнено одновременно и поле вознаграждения, и поле связанной привычки. Можно заполнить только одно из двух полей.
    * Время выполнения должно быть не больше 120 секунд.
    * В связанные привычки могут попадать только привычки с признаком приятной привычки.
    * У приятной привычки не может быть вознаграждения или связанной привычки.
    * Нельзя выполнять привычку реже, чем 1 раз в 7 дней.
    
    Для вывода списка привычек реализована пагинацию с выводом по 5 привычек на страницу.
    Проект содержит тесты, которые проверяют корректность работы CRUD модели привычки.
    
   
2. #### Приложение users 
##### Описание: 
    Создана модель «Пользователь» со следующими полями:   
    * все поля от обычного пользователя, но авторизацию заменить на email;
    * пароль,
    * аватар (изображение),
    * телефон,
    * город
        
    Электронная почта используется как поле для авторизации.
    Созданы CRUD для модели Пользователь. Для реализации CRUD использовано APIView.
    Каждый эндпоинт в проекте закрыт авторизацией, кроме регистрации и авторизации пользователей.
    В данном проекте использована JWT-авторизация.    
    Каждый пользователь имеет доступ только к своим привычкам по механизму CRUD.
    Пользователь может видеть список публичных привычек без возможности их как-то редактировать или удалять.
    Реализована работа с отложенными задачами для напоминания о том, в какое время какие привычки необходимо выполнять.
    Рассылка уведомлений осуществляется с помощью мессенджера Телеграм.
